Arsitektur Sistem

Usulan arsitektur web berlapis (3-tier) untuk sistem TemuBarang.

💻 📱
1. Presentation Layer

Browser desktop/mobile · HTML, CSS, JavaScript atau React

⚙️
2. Application Layer

REST API · autentikasi/otorisasi · validasi · logika laporan dan pencarian

🗄️
3. Data Layer

Database relasional · pengguna · laporan barang · kategori

Browser ⇄ API/Server ⇄ Database

Alur utama

  1. Pengguna membuka situs dan mencari laporan atau masuk ke akun.
  2. Pengguna membuat laporan dengan jenis, nama, kategori, tanggal, lokasi, deskripsi, dan foto opsional.
  3. Frontend mengirim data ke API melalui HTTPS; server memvalidasi input dan hak akses.
  4. API menyimpan data laporan ke database dan mengembalikan respons ke frontend.
  5. Fitur pencarian/filter mengambil laporan yang sesuai lalu menampilkannya.

Keamanan & kualitas

  • Hash kata sandi (jangan simpan kata sandi mentah).
  • Validasi input di sisi frontend dan backend.
  • Otorisasi: pengguna mengelola laporan miliknya; admin dapat memoderasi jika fitur admin ditambahkan.
  • HTTPS, pembatasan ukuran/tipe file, dan backup database.
  • Desain responsif, pesan error yang jelas, serta pengujian fungsional.

Catatan: pilihan framework dan hosting final disesuaikan dengan implementasi tim.

Rancangan Basis Data

Model awal yang selaras dengan akun pengguna dan postingan laporan.

users

nama
email (unik)
password_hash
role

PK category_id
nama_kategori
created_at

reports

PK report_id
FK user_id → users.user_id
FK category_id → categories.category_id
jenis (Hilang/Ditemukan)
nama_barang
deskripsi
lokasi
tanggal_kejadian
foto_url
status
created_at, updated_at

Relasi

users 1 — N reports
categories 1 — N reports

Index disarankan: reports(jenis), reports(category_id), reports(tanggal_kejadian), reports(nama_barang).

Catatan implementasi

  • Gunakan primary key untuk identitas unik setiap baris dan foreign key untuk menjaga konsistensi relasi.
  • Kolom email diberi constraint UNIQUE.
  • Kolom jenis dibatasi ke nilai Hilang atau Ditemukan.
  • Foto sebaiknya disimpan di object/file storage, sedangkan database menyimpan URL/path-nya.
  • Rancangan ini belum memasukkan modul pengelolaan penyimpanan fisik atau pencocokan AI karena berada di luar lingkup proposal.
